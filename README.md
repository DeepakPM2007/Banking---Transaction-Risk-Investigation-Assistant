# Banking — Transaction Risk Investigation Assistant

An AI-assisted fraud investigation tool that screens a customer's transaction history
against deterministic risk rules and generates an auditable investigation report via Gemini.

## Architecture (Core Design — Judging Criterion)

**Strict separation of deterministic logic and LLM reasoning:**

```
CSV Transaction History
        │
        ▼
┌──────────────────────────┐
│   Rule Engine (rules.py) │  ← pure Python, zero LLM, fully unit-tested
│   R1: Large transfer     │    outputs structured Finding objects
│   R2: New payee burst    │
│   R3: Odd-hours activity │
│   R4: Pattern break      │
└─────────────┬────────────┘
              │  only findings + cited txns sent to LLM (not full history)
              ▼
┌──────────────────────────┐
│   Gemini (llm.py)        │  ← report writer only — cannot invent findings
│   citation validated      │    falls back to template if LLM fails/hallucinates
└─────────────┬────────────┘
              ▼
     Structured JSON Report → FastAPI → Frontend
```

The LLM **never decides** whether something is suspicious — the rule engine does.
The LLM only synthesises verified findings into readable prose.

## How to Run

```bash
pip install -r requirements.txt
# set GEMINI_API_KEY in your environment or .env file
python app.py
# open http://localhost:8000
```

## Environment Variables

- `GEMINI_API_KEY` — your Google Gemini API key. **Never committed to the repo.**
  Set it in a `.env` file (excluded by `.gitignore`) or export it in your shell.

## Demo Data

Generated by `scripts/generate_data.py`. Two customers are pre-generated and committed:

- **clean_customer** — 150 routine transactions, no rule fires → green banner
- **layered_anomaly_customer** — 180 transactions with seeded anomalies (R1+R2+R3+R4 all fire) → red banner

To regenerate:
```bash
python scripts/generate_data.py
```

## Rule Thresholds

| Rule | Trigger | Severity |
|---|---|---|
| R1 Large Transfer | `amount > mean + 3×stddev` OR `> 2× customer historical max` | High |
| R2 New Payee Burst | Payee first seen < 7 days AND ≥2 payments totalling >3× avg in window | High |
| R3 Odd Hours | Transaction hour outside customer's own p10–p90 active-hours band | Medium |
| R4 Pattern Break | Channel differs from >80% baseline, or amount > p95 for that channel | Medium |
